# 余声生产级打磨设计

日期：2026-07-13
状态：已完成方向确认，待用户审阅书面设计

## 1. 产品定位

余声是一个经过声音本人授权、能用其声音与表达习惯进行低延迟有声对话的 AI 记忆陪伴产品。声音主人可以健在或已经离世，但两类场景使用不同的授权流程。产品始终明确生成内容是 AI 模拟，不宣称人物被“复活”，也不允许将生成内容冒充真人传播。

核心价值不是单纯克隆音色，而是同时还原以下五个维度：

1. 音色：听起来像声音主人。
2. 表达：用词、称呼、句长、口头禅和反应方式像本人。
3. 情绪：能根据上下文表现开放情绪、强度、语速和停顿。
4. 记忆：只引用有来源的真实记忆，不把模型猜测说成事实。
5. 对话感：用户说完后 4 秒内开始播放第一段声音。

## 2. 本次打磨范围

本次工作直接改进已上线产品，不另起一套“首版/第二版”。现有 Next.js 应用继续使用，逐步替换不适合生产环境的存储、认证和语音链路。

包含：

- 持久化数据库与私有声音存储。
- 声音授权、撤回、导出和彻底删除。
- 邮箱归属验证和生产级认证。
- 用户语音输入、按句生成、情绪控制和流式语音播放。
- 结构化人物档案和可追溯记忆。
- 模型超时、重试、降级、限流、成本和延迟监控。
- 单元、集成、端到端和真实供应商验收。
- Vercel 预览环境验证和生产部署。

不包含：

- 视觉风格、布局和设计 token 调整。
- 数字人形象、社交、公开分享、付费系统。
- 与核心声音对话无关的功能扩张。

录音、播放和情绪纠正所需的前端功能代码属于核心链路，允许修改，但不做视觉重设计。

## 3. 生产架构

### 3.1 存储

- 结构化数据：Neon Serverless Postgres。
- 原始参考声音：Vercel Private Blob，使用私有访问模式，不返回公开 URL。
- 向量检索：Postgres `pgvector`，继续使用 1024 维 bge-m3 embedding。
- 限流：Postgres 原子计数，不额外引入 Redis；规模增长后再替换实现。
- 本地开发：保留 local adapter，生产环境禁止回退到 SQLite 或本地声音目录。

存储访问统一放在 repository 和 object-store adapter 中。API 路由不直接写 SQL，也不直接调用 Blob SDK。所有现有同步数据库调用改为异步接口。

### 3.2 外部模型

- ASR：SiliconFlow SenseVoiceSmall。
- Embedding：SiliconFlow bge-m3。
- LLM：SiliconFlow DeepSeek-V3，输出结构化句子事件。
- TTS：SiliconFlow CosyVoice2 用户预置音色，启用流式输出和自然语言情绪控制。

每种能力都通过独立 provider interface 调用。当前默认供应商仍是 SiliconFlow，但路由和业务逻辑不依赖供应商特有响应格式。

### 3.3 部署

- Next.js 继续部署在现有 Vercel 项目。
- Preview 和 Production 使用独立数据库分支及独立 Blob 前缀。
- 生产函数部署到与数据库和主要用户更接近的可用区域；区域在真实延迟测量后固定，不使用默认值猜测。
- 使用 `STREAMING_VOICE_ENABLED` 控制新链路，旧文字对话和整段 TTS 作为短期回退，稳定后删除回退。

## 4. 数据模型

### 4.1 用户与授权

- `users`：账号、邮箱、密码摘要、状态、创建时间。
- `verification_codes`：验证码摘要、用途、过期时间、失败次数、使用时间。
- `voice_subjects`：声音主人，记录健在/已故、创建者和状态。
- `voice_consents`：授权人、授权版本、用途范围、授权时间、撤回时间和证据摘要。
- `audit_events`：授权、读取、导出、删除、远端音色创建和删除的审计记录。

在世声音必须由声音本人登录后单独授权。亲友不能替在世者授权。已故声音使用独立声明，记录上传者关系、素材来源和仅限私密使用的承诺。

### 4.2 声音与人物

- `voice_profiles`：声音主人、Blob pathname、音频校验和、文字稿、质量结果、供应商音色 ID、状态和删除时间。
- `personas`：人物基础信息和带版本号的结构化档案。
- 人物档案包含：称呼规则、口头禅、句长、语速、价值观、常见反应、禁忌、方言和不确定信息处理方式。

一个人物只绑定一个启用中的预置音色；重新录制时创建新版本，旧版本在切换成功后删除，不覆盖原对象。

### 4.3 记忆与对话

- `memories`：内容、类型、时间、参与者、来源、可信度、embedding 和状态。
- `messages`：角色、文本、状态、模型、耗时和创建时间。
- `message_sentences`：句子顺序、文本、情绪、强度、语速、停顿、用户覆盖值、TTS 状态和首字节耗时。
- `rate_limit_buckets`：账号、能力、时间窗口和调用次数。

记忆类型至少区分事实、共同经历、偏好和说话习惯。模型生成内容不得自动写回真实记忆。

## 5. 核心语音数据流

1. 用户按住说话或结束录音后，将音频提交到受鉴权的对话入口。
2. 服务端校验人物归属、授权状态、文件类型、时长和限流。
3. ASR 将用户音频转成文本；失败时保留重新录音和文字输入回退。
4. 安全分类先判断自伤、威胁、诈骗和冒充风险；高风险回复不进入人物扮演。
5. 检索真实记忆和人物档案，交给 LLM 生成短句事件：
   - `text`
   - `emotion`
   - `intensity`（0-100）
   - `speed`
   - `pause_after_ms`
6. 第一条完整句子一产生就立即调用流式 TTS，不等待整段回复完成。
7. 客户端按顺序播放音频流；后续句子在队列中并行准备，但不得乱序播放。
8. 文本、情绪判断、延迟和失败原因写入消息记录。
9. 用户纠正情绪时，只重新生成对应句子的语音，不重新调用 LLM，也不覆盖原始判断。

目标时延按用户停止说话后计算：

- ASR 完成：目标 1.2 秒内。
- 第一条句子生成：累计 2.4 秒内。
- 第一段音频开始播放：累计 4 秒内。
- 验收口径：真实预览环境连续 20 轮对话，至少 80% 达标。

## 6. 情绪控制

产品支持开放情绪，但不直接把任意自由文本无约束地传给 TTS。LLM 先输出标准字段，再由 emotion mapper 转换成供应商可执行的自然语言指令。

标准字段包括：情绪名称、强度、语速、音高倾向、音量倾向、停顿和是否带笑/哽咽等可选表现。若结构化结果无效，回退到人物默认语气，不猜测极端情绪。

用户可以修改情绪名称和强度。纠正记录用于计算情绪纠正率，但未经声音本人同意，不用于外部模型训练。

## 7. 认证、安全与数据权利

- 新账号必须先验证邮箱归属，再设置至少 10 位密码。
- 验证码使用加密安全随机数，数据库只保存摘要；限制发送频率、验证次数和总尝试次数。
- Session cookie 保持 `HttpOnly`、`Secure`、`SameSite=Lax`，敏感写操作校验 Origin。
- 每次声音读取、预置音色创建、导出和删除都校验当前用户权限和有效授权。
- 参考声音和文字稿不写日志；供应商错误信息在返回用户前脱敏。
- 所有 AI 对话和合成音频明确标注为 AI 生成；系统提示词不得否认 AI 身份。

撤回授权触发删除流程：

1. 立即禁止新对话和新 TTS。
2. 删除供应商预置音色。
3. 删除 Private Blob 原始声音。
4. 软删除人物可见数据并按用户选择删除对话；法定审计记录只保留最小必要字段。
5. 任一步失败都进入可重试状态并记录审计，不向用户虚报“已彻底删除”。

## 8. 错误处理与降级

- 所有供应商请求使用 `AbortSignal.timeout`，按能力设置独立超时。
- 仅对网络错误、429 和 5xx 做有限次数指数退避；鉴权错误、参数错误不重试。
- ASR 失败：允许重新录音或改用文字，不生成猜测文本。
- LLM 结构错误：尝试一次结构修复，仍失败则使用短文本安全回退。
- TTS 失败：保留文字，允许重试当前句；不切换成错误人物的声音。
- 数据库写入失败：不把未持久化的回复标记为成功。
- Blob 上传与数据库写入采用两阶段状态；失败时清理孤儿对象。
- 供应商不可用时保留旧文字对话回退，但明确提示语音暂时不可用。

## 9. 可观测性与产品指标

每轮对话记录以下不含原始音频的指标：

- ASR、首句、TTS 首字节和首段播放耗时。
- 各供应商状态码、超时、重试次数和调用成本估算。
- 记忆召回数量与引用情况。
- 情绪纠正率、TTS 重试率、对话完成率。
- 授权撤回和删除任务状态。

北极星指标为“有效还原会话率”：用户对声音像本人、表达像本人和情绪准确度均评分至少 4/5，且不适感不高于 2/5 的会话比例。上线打磨完成不以页面可访问或构建成功为依据，必须有真实对话和真实存储读回证据。

## 10. 测试与验收

### 10.1 自动化测试

- 单元测试：情绪映射、人物提示词、记忆筛选、验证码、限流、删除状态机、供应商错误分类。
- 数据库集成测试：迁移、用户隔离、事务、级联/软删除、pgvector 查询、幂等写入。
- API 测试：注册、登录、上传、授权、创建人物、对话、情绪纠正、撤回和删除。
- 浏览器端到端测试：使用测试账号完成录音、人物创建、三轮对话和删除。

单元测试可以使用 provider fake 验证错误分支，但不得把 fake 结果当作上线成功。最终验收必须调用真实 SiliconFlow、真实 Neon 和真实 Private Blob。

### 10.2 生产前验收门槛

以下项目全部通过才允许切换生产：

1. 类型检查、构建、单元测试、数据库集成测试和端到端测试通过。
2. 两个测试账号互相不能读取人物、记忆、声音或对话。
3. 真实参考声音可创建预置音色并完成三轮有声对话。
4. 连续 20 轮真实对话中至少 80% 在 4 秒内开始播放第一段声音。
5. 撤回授权后，新对话立即被拒绝；数据库、Blob 和供应商音色均验证已删除。
6. 供应商超时、429、5xx 和无效结构均有明确回退，不返回 HTML 错误页。
7. Production 环境没有 SQLite、本地声音目录或默认 session secret 回退。

## 11. 数据迁移与上线顺序

1. 增加 Postgres schema、repository adapter、Private Blob adapter 和迁移工具，不改变现有生产流量。
2. 迁移工具支持 dry-run、校验和、幂等重跑和逐项报告；从可获得的 SQLite 与 `data/voices` 导入。
3. 在 Preview 创建独立 Neon 分支和 Private Blob 前缀，完成自动化与真实供应商验证。
4. 上线认证和授权流程，禁止新声音继续写入本地磁盘。
5. 上线预置音色、结构化人物档案和按句流式语音链路，并保留功能开关。
6. 观察错误率、删除任务和延迟；达到验收门槛后打开生产功能开关。
7. 确认无回退依赖后，删除生产 SQLite、本地 voiceStore 和旧整段 TTS 路径。

如果线上旧数据因 Serverless 临时磁盘已经不可读取，迁移报告必须明确列出缺失对象，不能伪造迁移成功。

## 12. 完成定义

本次生产打磨只有在以下事实同时成立时才算完成：

- 线上用户数据持久化且可恢复。
- 授权、撤回和彻底删除链路有真实读回证据。
- 用户能使用语音完成连续对话，第一段声音延迟达到目标。
- 情绪自动判断、用户纠正和单句重生成可用。
- 人物表达和记忆有结构化约束，不再依赖一段自由描述。
- 真实供应商、真实数据库、真实 Blob 和生产预览环境全部验证通过。
- 生产部署完成，监控没有发现阻断性错误。
