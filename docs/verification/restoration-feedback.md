# 有效还原会话证据口径

> 更新：2026-07-15（Asia/Shanghai）
> 用途：统一 0→1 产品验证口径；不将本地测试冒充为真实用户证据。

## 一句话结论

本地代码已能记录会话、句子、TTS 尝试、浏览器播放事件和不可修改的评分，并按健在组/逝者组分开聚合。但真实 Preview 浏览器、真实语音供应商、真实数据库回读和认识声音主人的用户评价都还没有被证明，所以当前不能宣称产品核心价值已成立。

## 什么算一次有效还原

评价人必须认识声音主人，确认自己听完本次评分所依据的所有轮次。一次可评分会话至少有 3 个不同的可听对话轮次，每个轮次必须同时满足：

- 对话轮次已完成，模式为 `grounded` 或 `companionship`；
- 语音跟踪没有失败；
- 至少一次 TTS 尝试已完成；
- 该尝试收到浏览器上报的 `play_started`。

只要该会话仍有 `started` 状态的对话轮次或 TTS 尝试，系统就拒绝评分，避免把尚未结束的过程误算成有效样本。

评分包含 5 项 1–5 分指标：

- 声音相似度；
- 表达习惯相似度；
- 情绪合适度；
- 事实可信度；
- 不适感。

只有前 4 项全部不低于 4/5，不适感不高于 2/5，并且以下 3 条红线全部为“否”，这次会话才算有效还原：

- 重大事实编造；
- 身份冒充；
- 授权越界。

任意一条红线命中都会直接判定该会话无效，不能被高分抵消。

## 0→1 门槛

健在组和逝者组必须分开计算，每组都要同时达到：

- 至少 10 位不同的评价人；
- 至少 30 次有效评分会话；
- 有效还原会话率至少 60%。

只有两组同时达标，`bothCohortsMeetInitialGate` 才能是 `true`。空数据必须输出人数/会话数/成功数为 `0`、比率为 `null`、两组均不达标，绝不能默认通过。

## 首轮小样本干跑

首轮只做健在 2 人 + 逝者 2 人，每人 3 次可评分会话。它用于找出流程、评分、数据归属和失败样本的问题，不代表产品通过。0→1 最终仍以每组 10 人 / 30 次会话 / 60% 为门槛。

自动化测试、伪造评分、虚构人物探针和合成数据只能证明计算与边界逻辑，不能作为真实用户证据，不能写入对外的达标数字。

## 运行报告

在已正确配置的环境运行：

```bash
npm run --silent report:restoration
```

必须保留 `--silent`；否则 npm 会把包名和实际命令横幅写入标准输出，下游就无法把整段输出当作 JSON 解析。

该命令是全局运营聚合命令，不经用户 API，也没有新增公开路由。它只读取会话 ID、评价人 ID、健在/逝者分组、5 项分数和 3 条红线。查询和输出均不包含邮箱、人物名、评语、句子或转写、声音/供应商 ID、音频路径。SQLite 和 Postgres 共用同一份字段白名单、SELECT 和映射口径，避免两个适配器慢慢算成两套指标。

本地 SQLite 报告不调用业务 `getDb()`，不创建目录/数据库，不初始化 schema，不跑 migration，不修改源库 pragma。只有打开源文件时明确返回 `ENOENT` 才按空数据输出 zero/null/false，且不生成 `yusheng.sqlite`；权限拒绝、路径不是目录或其他文件系统错误都返回稳定 `report_unavailable`，不会被伪装成“没数据”。

已存在的数据库通过同一个只读文件句柄获取复制前/后指纹（设备、inode、大小、纳秒级 mtime/ctime），并串流复制到系统临时目录，不把整库读入 JavaScript 内存。复制前或复制后发现 `-wal` / `-shm` / `-journal`，或两次指纹不同，就丢弃快照并返回 `report_unavailable`，不输出可能过时的报告。SQLite 只会打开临时副本，该目录包括临时边车文件都在 `finally` 删除；源目录不新增文件，源文件指纹不变。未迁移到评分表的旧库同样稳定失败，不会被报告命令暗中升级。

本地报告的 SQLite 文件上限是 **256 MiB**。该上限在复制前由 `fstat` 检查，目的是把临时磁盘占用明确限制在约一份 256 MiB 数据库加少量 SQLite 临时文件，并避免大库进入本地运营命令。超限时只返回 `report_unavailable`；需要统计更大数据时应使用 Postgres 聚合路径或单独的受控导出，不应调高内存占用来硬跑。

Postgres 路径只执行指标 SELECT，不运行 migration，不写任何表。

配置或存储失败时，命令只向标准输出写入：

```json
{"error":"report_unavailable"}
```

同时非 0 退出；不输出原始异常、连接串或密钥。

## 证据边界

- 浏览器非视觉事件发送已在本地代码接线，详见 [playback-telemetry.md](./playback-telemetry.md)。
- `play_started` 是客户端自证，只证明浏览器报告开始播放，不证明用户听完。“已听完所有轮次”仍需评价人明确确认。
- TTS 成功只证明音频合成完成，不等于浏览器已播放，更不等于用户已听完。
- 真实 Preview 浏览器 + 真实 provider + 真实 DB readback 仍是未完成门槛。
- 推送 Git、自动创建 Preview、验证 Preview 和更新 Production 是分开的门槛。本地报告通过不授权 push，也不授权上线。
